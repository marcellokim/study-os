PYTHON_BIN="${PYTHON:-python3.13}"

if [[ ! -d "$ENGINE_ROOT/study_os" ]]; then
  echo "error: Study OS engine not found at $ENGINE_ROOT" >&2
  exit 1
fi

if ! command -v "$PYTHON_BIN" >/dev/null 2>&1; then
  echo "error: Python executable not found: $PYTHON_BIN" >&2
  echo "hint: set PYTHON=/path/to/python3.10+ or install python3.13" >&2
  exit 1
fi

PYTHONPATH="$ENGINE_ROOT${PYTHONPATH:+:$PYTHONPATH}" \
  "$PYTHON_BIN" -m study_os --workspace "$WORKSPACE_ROOT" "$@"
WRAPPER
chmod +x /Users/ydmac/Documents/study-workspace/study-os

# Study OS Operator

Operate the runtime workspace at `/Users/ydmac/Documents/study-workspace` using the engine at `/Users/ydmac/Documents/study-os`.

## Mode boundary

This skill is for course operation, not engine development.

Do not edit engine code. Do not directly edit canonical state files such as `mastery.json`, `review_queue.yaml`, `error_log.jsonl`, or `session_history.jsonl`. Use `./study-os` commands for state changes.

Original source files under `courses/<course_slug>/sources/` are user-owned. Read them, but do not delete or rewrite them.

## Common workflow: decompose a course

1. Identify the target course slug from the prompt or from `courses/`.
2. Run `./study-os status --course <course_slug>` if the course is already initialized; if it is not initialized, continue with source inspection.
3. Refresh source inventory when files may have changed:

   ```bash
   PYTHONPATH=/Users/ydmac/Documents/study-os python3.13 /Users/ydmac/Documents/study-os/scripts/prepare_real_course.py \
     --workspace /Users/ydmac/Documents/study-workspace \
     --course-slug <course_slug> \
     --course-name "<course name>" \
     --exam-date <YYYY-MM-DD> \
     --overwrite
   ```

4. Read `courses/<course_slug>/init_request.json` and inspect `source_manifest`.
5. Read the relevant syllabus, slides, transcripts, notes, and image references from `sources/`.
6. Replace the placeholder `source_inventory` block/item with real exam-scope `blocks` and recallable `items`.
7. Preserve source paths in `source_manifest`; add `visual_requirements` for diagram-dependent items.
8. Run:

   ```bash
   ./study-os init-course --request-file courses/<course_slug>/init_request.json --validate-sources
   ```

9. Report the number of blocks/items, generated files, and the next recommended study command.

## Common workflow: start a study day

1. Run `./study-os status --course <course_slug>`.
2. Pick or confirm the next `day_index` from course state and user intent.
3. Run:

   ```bash
   ./study-os start-day --course <course_slug> --day <N> --today <YYYY-MM-DD>
   ```

4. Summarize the learning and recall packet paths.

## Common workflow: close a session

1. Convert the user's study results into a close-session request JSON.
2. Use `result` values only from `correct`, `wrong`, `partial`, or `uncertain`.
3. Use `confidence` values only from `low`, `medium`, `high`, or `unknown`.
4. Include `error_code` only when a mistake category is known.
5. Run:

   ```bash
   ./study-os close-session --request-file <close_request.json>
   ```

6. Report warnings, held items, updated queue status, and next action.

## Common workflow: final recall/status

- Status:

  ```bash
  ./study-os status --course <course_slug>
  ```

- Final recall:

  ```bash
  ./study-os start-final-recall --course <course_slug> --today <YYYY-MM-DD>
  ```

## Reporting contract

Keep reports concise and evidence-backed:

- Course slug
- Files read or changed
- Commands run
- Generated outputs
- Next study action
- Any source or validation blockers
SKILL
